# Checkbox

The `Checkbox` component is a flexible and reusable selection control designed for FlowForge forms and business applications.

It provides a consistent API for boolean values while supporting common form states, descriptions, validation feedback, sizing, indeterminate behavior, responsive layouts, and form-field alignment.

---

## Overview

`Checkbox` is one of the core form components of FlowForge.

It can be used independently or as part of a form generated by the FlowForge Form Builder.

### Key Features

- Labels
- Descriptions
- Controlled usage
- Uncontrolled usage
- Checked state
- Indeterminate state
- Required state
- Disabled state
- Validation errors
- Small, medium, and large sizes
- Full-width layout
- Alignment with other form fields
- Field wrapper integration
- React state integration

## Basic Usage

The simplest way to use `Checkbox` is to provide a label.


## Controlled Checkbox

`Checkbox` supports the standard React controlled component pattern.

```tsx
import { useState } from "react";
import { Checkbox } from "@/engine/components";

export default function Example() {
  const [checked, setChecked] = useState(false);

  return (
    <Checkbox
      label="Enable notifications"
      checked={checked}
      onChange={setChecked}
    />
  );
}
```

The `checked` value is controlled by React state and updated through the `onChange` callback.

The `onChange` callback receives the new boolean value.

## Checked State

The `checked` property controls whether the Checkbox is selected.

```tsx
<Checkbox
  label="Enable feature"
  checked
/>
```

For controlled usage:

```tsx
const [checked, setChecked] = useState(false);

<Checkbox
  label="Enable feature"
  checked={checked}
  onChange={setChecked}
/>
```

The value passed to `onChange` is the new checked state.

## Indeterminate State

The `indeterminate` property represents a partially selected state.

This is useful when a Checkbox represents the state of a group of items where some, but not all, items are selected.

```tsx
<Checkbox
  label="Select all"
  indeterminate
/>
```

A common controlled implementation is:

```tsx
import { useState } from "react";
import { Checkbox } from "@/engine/components";

export default function Example() {
  const [checked, setChecked] = useState(false);
  const [indeterminate, setIndeterminate] = useState(true);

  const handleChange = (value: boolean) => {
    setChecked(value);
    setIndeterminate(false);
  };

  return (
    <Checkbox
      label="Select all"
      description="Clicking the Checkbox resolves the indeterminate state."
      checked={checked}
      indeterminate={indeterminate}
      onChange={handleChange}
    />
  );
}
```

Once the user changes the Checkbox, the indeterminate state can be cleared and replaced by the normal checked or unchecked state.

## Form Alignment

The `alignWithField` property is designed for form layouts where a Checkbox should align with the control area of another form field.

This is particularly useful when different field types are placed in columns.

```tsx
<div className="form-grid">

  <Input
    label="First Name"
    placeholder="Enter first name"
  />

  <Checkbox
    label="Active"
    description="User can access the application."
    alignWithField
  />

</div>
```

When `alignWithField` is enabled, the Checkbox uses an empty label slot in its `FieldWrapper`.

This preserves the vertical space normally occupied by a form field label, allowing the Checkbox control to align with the control area of neighboring fields.

The default value of `alignWithField` is `false`.

### Two-column Form Example

```tsx
<div className="form-grid">

  <div>
    <Input
      label="First Name"
      placeholder="Enter first name"
    />

    <Input
      label="Last Name"
      placeholder="Enter last name"
    />

    <Input
      label="Email"
      placeholder="Enter email"
    />
  </div>

  <div>
    <Checkbox
      label="Active"
      description="User can access the application."
      alignWithField
    />

    <Checkbox
      label="Verified"
      description="The user's email address has been verified."
      alignWithField
    />

    <Checkbox
      label="Notifications"
      description="User can receive application notifications."
      alignWithField
    />
  </div>

</div>
```

## Controlling Form Alignment

The `alignWithField` property can be controlled using React state.

```tsx
import { useState } from "react";
import { Checkbox } from "@/engine/components";

export default function Example() {
  const [alignWithField, setAlignWithField] =
    useState(true);

  return (
    <Checkbox
      label="Align With Field"
      checked={alignWithField}
      onChange={setAlignWithField}
      withWrapper={false}
    />
  );
}
```

The controlled value can then be passed to another Checkbox:

```tsx
<Checkbox
  label="Active"
  description="User can access the application."
  alignWithField={alignWithField}
/>
```

This allows the form layout to switch between aligned and non-aligned states.

## Field Wrapper

By default, `Checkbox` is rendered inside a `FieldWrapper`.

The `FieldWrapper` provides the surrounding field structure used by FlowForge form components and is responsible for features such as:

- Helper text
- Validation errors
- Tooltips
- Full-width field layout
- Consistent field structure
- Optional label spacing for field alignment

The Checkbox itself still renders its own label and description next to the checkbox control.

When `alignWithField` is enabled, the `FieldWrapper` receives an empty label slot to preserve the vertical structure of regular form fields.

---

## Without Field Wrapper

The `withWrapper` property can be set to `false` when the Checkbox is embedded inside another component or layout that already manages the field structure.

```tsx
<Checkbox
  label="Enabled"
  withWrapper={false}
/>
```

This is useful for contexts such as:

- Editable tables
- Compact control groups
- Custom layouts
- Components that already provide their own field wrapper

When `withWrapper` is `false`, the Checkbox renders its own control directly without the surrounding `FieldWrapper`.

The default value of `withWrapper` is `true`.

## API

### CheckboxProps

| Property | Type | Default | Description |
| --- | --- | --- | --- |
| `label` | `ReactNode` | — | Label displayed beside the Checkbox |
| `description` | `ReactNode` | — | Supporting text displayed below the Checkbox label |
| `checked` | `boolean` | — | Controlled checked state |
| `defaultChecked` | `boolean` | — | Initial checked state for uncontrolled usage |
| `onChange` | `(checked: boolean) => void` | — | Callback triggered when the checked value changes |
| `size` | `"sm" \| "md" \| "lg"` | `"md"` | Controls the Checkbox size |
| `required` | `boolean` | `false` | Marks the Checkbox as required |
| `disabled` | `boolean` | `false` | Disables user interaction |
| `error` | `string` | — | Validation error message |
| `indeterminate` | `boolean` | `false` | Displays the Checkbox in an indeterminate state |
| `fullWidth` | `boolean` | `false` | Makes the Checkbox occupy the available width |
| `alignWithField` | `boolean` | `false` | Adds an empty label slot to the `FieldWrapper` so the Checkbox aligns with neighboring form controls |
| `withWrapper` | `boolean` | `true` | Controls whether the Checkbox is rendered inside a `FieldWrapper` |
| `tooltip` | `ReactNode` | — | Optional tooltip displayed by the `FieldWrapper` |
| `className` | `string` | — | Optional class name applied to the Checkbox root |

## Accessibility

`Checkbox` is designed around standard checkbox interaction behavior.

Use meaningful labels so that the purpose of the control is clear to users and assistive technologies.

Recommended usage:

```tsx
<Checkbox
  label="Receive email notifications"
  description="You will receive notifications about account activity."
/>
```

Required and disabled states should be used consistently with the surrounding form semantics.

When a Checkbox represents a group of controls, the indeterminate state can communicate that only part of the group is selected.

## Responsive Behavior

The Checkbox is designed to work within responsive form layouts.

Higher-level layout systems are responsible for defining the number of columns and responsive behavior.

For example:

```tsx
<div className="form-grid">

  <div>
    <Input
      label="First Name"
      placeholder="Enter first name"
    />
  </div>

  <div>
    <Checkbox
      label="Active"
      alignWithField
    />
  </div>

</div>
```

The `alignWithField` property does not control the layout grid itself.

Instead, it preserves the label space inside the Checkbox's `FieldWrapper`, allowing the Checkbox to align vertically with controls belonging to neighboring fields.

## Form Engine Integration

The Checkbox is designed to be used as a building block for the FlowForge Form Engine.

A form definition can describe a boolean field using configuration similar to:

```ts
{
  type: "checkbox",
  name: "active",
  label: "Active",
  required: true
}
```

The Form Builder can resolve the field definition to the corresponding FlowForge component.

```text
Form Definition
      ↓
Form Builder
      ↓
Field Registry
      ↓
Checkbox
      ↓
Form Engine
      ↓
Validation / Dependencies / State
```

This keeps the Checkbox component independent from business-specific form logic.

---

## Validation

Validation is intentionally separated from the visual Checkbox component.

The Checkbox is responsible for displaying the validation state:

```tsx
<Checkbox
  label="Accept terms"
  error="Please select this option."
/>
```

The Form Engine can be responsible for defining and executing validation rules.

This separation allows the same Checkbox component to work independently as well as inside dynamically generated forms.
