# Input

The `Input` component is a flexible and reusable text input field designed for FlowForge forms and applications.

It provides a consistent API for common input requirements while handling states, validation feedback, loading behavior, adornments, and responsive layout.

---

## Overview

`Input` is one of the core field components of FlowForge.

It can be used independently or as part of a form generated by the FlowForge Form Builder.

### Key Features

- Labels
- Helper text
- Validation errors
- Required state
- Disabled state
- Loading state
- Clearable input
- Prefix and suffix
- Start and end adornments
- Small, medium, and large sizes
- Full-width layout
- Controlled and uncontrolled usage
- React ref support

---

## Controlled Input

`Input` supports the standard React controlled input pattern.

```tsx
import { useState } from "react";
import { Input } from "@/engine/components/form";

export default function Example() {
  const [value, setValue] = useState("");

  return (
    <Input
      label="Name"
      value={value}
      onChange={(event) =>
        setValue(event.target.value)
      }
      placeholder="Enter your name"
    />
  );
}
```

## Full Width

Use `fullWidth` when the input should occupy the available horizontal space.

```tsx
<Input
  label="Email"
  placeholder="Enter your email"
  fullWidth
/>
```

The default value of `fullWidth` is `false`.

When `fullWidth` is `true`, the input occupies the available width of its parent container.

```tsx
<Input
  label="Email"
  fullWidth
/>
```

When `fullWidth` is `false`, the input keeps its content-based layout.

```tsx
<Input
  label="Email"
  fullWidth={false}
/>
```

The Interactive Playground allows this behavior to be changed using the `Full Width` control.

[Open Full Width in Playground](/playground/input?focusId=input-interactive)

## Loading State

The `loading` state disables the input and displays a loading indicator.

```tsx
<Input
  label="Username"
  loading
  loadingText="Checking username..."
/>
```

This is useful when an asynchronous operation is being performed.

For example:

```text
User enters username
        ↓
API request
        ↓
Input enters loading state
        ↓
Server response
        ↓
Validation result
```

The Playground demonstrates the loading state inside the `States` section.

[Open Loading State in Playground](/playground/input?focusId=input-states&innerFocusId=input-state-loading)

## Clearable Input

Use `clearable` to display a clear action when the input contains a value.

```tsx
<Input
  label="Search"
  value="FlowForge"
  clearable
  onClear={() => {
    console.log("Input cleared");
  }}
/>
```

The `onClear` callback is called when the user activates the clear action.

## Without Field Wrapper

By default, `Input` uses `FieldWrapper` to provide the label, helper text, validation error, and required state.

This behavior can be disabled using `withWrapper`.

```tsx
<Input
  placeholder="Standalone input"
  withWrapper={false}
/>
```

This is useful when the surrounding UI already provides its own field layout.

## Ref Support

`Input` uses `forwardRef`, allowing consumers to access the underlying native HTML input element.

```tsx
import { useRef } from "react";
import { Input } from "@/engine/components/form";

export default function Example() {
  const inputRef = useRef<HTMLInputElement>(null);

  const handleFocus = () => {
    inputRef.current?.focus();
  };

  return (
    <>
      <Input
        ref={inputRef}
        label="Name"
        placeholder="Enter your name"
      />

      <button
        type="button"
        onClick={handleFocus}
      >
        Focus Input
      </button>
    </>
  );
}
```

## API

### InputProps

| Property | Type | Default | Description |
| --- | --- | --- | --- |
| `label` | `string` | — | Label displayed above the input |
| `helperText` | `string` | — | Supporting text displayed below the input |
| `error` | `string` | — | Validation error message |
| `size` | `"sm" \| "md" \| "lg"` | `"md"` | Controls the input size |
| `fullWidth` | `boolean` | `false` | Makes the input occupy the available width |
| `startAdornment` | `ReactNode` | — | Content displayed before the input |
| `endAdornment` | `ReactNode` | — | Content displayed after the input |
| `loading` | `boolean` | `false` | Displays a loading state |
| `loadingText` | `string` | — | Placeholder displayed while loading |
| `clearable` | `boolean` | `false` | Enables the clear action |
| `onClear` | `() => void` | — | Callback triggered when the input is cleared |
| `prefix` | `ReactNode` | — | Content displayed before the input value |
| `suffix` | `ReactNode` | — | Content displayed after the input value |
| `withWrapper` | `boolean` | `true` | Enables or disables `FieldWrapper` |

In addition to these properties, `Input` supports the standard HTML `<input>` attributes.

## Native Input Attributes

Because `InputProps` extends the native React input attributes, standard properties can also be used.

For example:

```tsx
<Input
  type="email"
  name="email"
  autoComplete="email"
  maxLength={100}
  placeholder="Enter your email"
/>
```

Other native input properties such as `name`, `value`, `defaultValue`, `onChange`, `required`, `disabled`, `readOnly`, `type`, and `placeholder` are also supported.

## Validation

Validation is intentionally separated from the visual input component.

The `Input` component is responsible for displaying validation state:

```tsx
<Input
  label="Email"
  error="Please enter a valid email address."
/>
```

The Form Engine will be responsible for defining and executing validation rules.

This separation allows the same input component to work independently as well as inside dynamically generated forms.

[Open Validation State in Playground](/playground/input?focusId=input-states&innerFocusId=input-state-error)

## Accessibility

`Input` is designed to work with standard HTML input behavior and should be used with meaningful labels and accessible descriptions.

Recommended usage:

```tsx
<Input
  label="Email address"
  type="email"
  required
  helperText="We will never share your email."
/>
```

When using icons or custom adornments, ensure that purely decorative icons are not exposed as meaningful content to assistive technologies.

---

## Responsive Behavior

The component is designed to work within responsive form layouts.

When `fullWidth` is enabled:

```tsx
<Input
  label="Email"
  fullWidth
/>
```

the input uses the available width of its parent container.

The Interactive Playground allows the `fullWidth` property to be toggled interactively.

[Open Full Width Behavior in Playground](/playground/input?focusId=input-interactive)

Responsive form layout and field positioning are handled by higher-level FlowForge form layout and Form Engine systems.

## Form Builder Integration

`Input` is intended to be used as a building block for the FlowForge Form Builder.

A future form definition may describe a field using configuration similar to:

```ts
{
  type: "input",
  name: "firstName",
  label: "First name",
  required: true
}
```

The Form Builder can then resolve the field type to the corresponding FlowForge component.

```text
Form Definition
      ↓
Form Builder
      ↓
Field Registry
      ↓
Input
      ↓
Form Engine
      ↓
Validation / Dependencies / State
```

## Design Considerations

`Input` is intentionally kept independent from business-specific validation and form logic.

Its responsibilities are primarily:

1. Rendering the input.
2. Managing visual states.
3. Providing a consistent API.
4. Supporting common interaction patterns.
5. Integrating with `FieldWrapper`.
6. Exposing standard native input behavior.

Higher-level concerns such as validation rules, dependencies, conditional rendering, form state, persistence, and submission are handled by the FlowForge Form Engine.

## Architecture Note

The `Input` component is part of the FlowForge UI layer.

It should remain independent from the backend and database implementation.

```text
┌──────────────────────────────┐
│          FlowForge UI        │
│                              │
│  Input / Select / Textarea   │
│             ↓                │
│        Form Builder          │
│             ↓                │
│         Form Engine          │
└──────────────┬───────────────┘
               │
               ↓
┌──────────────────────────────┐
│           Service            │
│                              │
│       API / Auth / ACL       │
│             ↓                │
│          Supabase            │
│             ↓                │
│         PostgreSQL           │
└──────────────────────────────┘
```

This separation allows the FlowForge UI layer and Service layer to evolve independently.
