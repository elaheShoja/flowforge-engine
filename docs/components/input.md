# Input

The `Input` component is a flexible and reusable text input field designed for FlowForge forms and business applications.

It provides a consistent API for common input requirements while supporting form states, validation feedback, loading behavior, clearable inputs, adornments, sizing, and responsive layouts.

---

## Overview

`Input` is one of the core form components of FlowForge.

It can be used independently or as part of a form generated by the FlowForge Form Engine.

### Key Features

- Labels
- Helper text
- Validation errors
- Required state
- Disabled state
- Loading state
- Clearable input
- Prefix and suffix
- Start and end adornments
- Small, medium, and large sizes
- Full-width layout
- Controlled and uncontrolled usage
- Native HTML input attributes
- React ref support
- Field wrapper integration

## Controlled Input

`Input` supports the standard React controlled input pattern.

```tsx
import { useState } from "react";
import { Input } from "@/engine/components";

export default function Example() {
  const [value, setValue] = useState("");

  return (
    <Input
      label="Name"
      value={value}
      onChange={(event) =>
        setValue(event.target.value)
      }
      placeholder="Enter your name"
    />
  );
}
```

The `value` is controlled by React state and updated through the native `onChange` event.

## Full Width

Use `fullWidth` when the input should occupy the available horizontal space of its parent container.

```tsx
<Input
  label="Email"
  placeholder="Enter your email"
  fullWidth
/>
```

The default value of `fullWidth` is `false`.

When `fullWidth` is enabled, the input expands to use the available width of its parent container.

```tsx
<Input
  label="Email"
  fullWidth={false}
/>
```

When disabled, the input keeps its content-based layout.

[Open Full Width in Playground](/playground/input?focusId=input-interactive)

## Required Input


## Helper Text

Use `helperText` to provide additional information about the field.

```tsx
<Input
  label="Username"
  helperText="Your username must be at least 3 characters."
  placeholder="Enter username"
/>
```

Helper text is displayed below the input and can be used to communicate usage requirements or additional context.

## Validation Error

The `error` property displays validation feedback associated with the input.

```tsx
<Input
  label="Email"
  value="invalid-email"
  error="Please enter a valid email address."
/>
```

The Input component is responsible for displaying the visual error state.

Higher-level form logic can provide the validation result and error message when the component is used inside a generated form.

## Loading State

The `loading` property disables the input and displays a loading indicator.

```tsx
<Input
  label="Username"
  loading
  loadingText="Checking username..."
/>
```

This is useful when an asynchronous operation is being performed.

A typical interaction can be represented as:

```text
User enters value
        ↓
API request
        ↓
Input enters loading state
        ↓
Server response
        ↓
Validation result
```

[Open Loading State in Playground](/playground/input?focusId=input-states&innerFocusId=input-state-loading)

## Clearable Input

Use `clearable` to display a clear action when the input contains a value.

```tsx
<Input
  label="Search"
  value="FlowForge"
  clearable
  onClear={() => {
    console.log("Input cleared");
  }}
/>
```

The `onClear` callback is called when the user activates the clear action.

A clearable input is useful for search fields and other inputs where quickly removing the current value improves usability.

## Start and End Adornments

Adornments can be used to display icons or other React elements around the input control.

### Start Adornment

```tsx
import { Search } from "lucide-react";

<Input
  label="Search"
  startAdornment={<Search size={18} />}
  placeholder="Search..."
/>
```

### End Adornment

```tsx
import { Search } from "lucide-react";

<Input
  label="Search"
  placeholder="Search..."
  endAdornment={<Search size={18} />}
/>
```

`startAdornment` and `endAdornment` accept React elements, making them suitable for icons and other contextual UI.

When using decorative icons, ensure that they do not expose unnecessary semantic information to assistive technologies.

## Without Field Wrapper

By default, `Input` uses `FieldWrapper` to provide the label, helper text, validation error, required state, and field layout.

This behavior can be disabled using `withWrapper`.

```tsx
<Input
  placeholder="Standalone input"
  withWrapper={false}
/>
```

This is useful when the surrounding UI already provides its own field structure.

## Ref Support

`Input` supports React refs and exposes the underlying native HTML input element.

```tsx
import { useRef } from "react";
import { Input } from "@/engine/components";

export default function Example() {
  const inputRef = useRef<HTMLInputElement>(null);

  const handleFocus = () => {
    inputRef.current?.focus();
  };

  return (
    <>
      <Input
        ref={inputRef}
        label="Name"
        placeholder="Enter your name"
      />

      <button
        type="button"
        onClick={handleFocus}
      >
        Focus Input
      </button>
    </>
  );
}
```

This allows consumers to use native input methods such as `focus()` when required.

## API

### InputProps

| Property | Type | Default | Description |
| --- | --- | --- | --- |
| `label` | `string` | — | Label displayed for the input |
| `helperText` | `string` | — | Supporting text displayed below the input |
| `error` | `string` | — | Validation error message |
| `size` | `"sm" \| "md" \| "lg"` | `"md"` | Controls the input size |
| `fullWidth` | `boolean` | `false` | Makes the input occupy the available width |
| `startAdornment` | `ReactNode` | — | Content displayed before the input |
| `endAdornment` | `ReactNode` | — | Content displayed after the input |
| `loading` | `boolean` | `false` | Displays the loading state |
| `loadingText` | `string` | — | Text displayed while loading |
| `clearable` | `boolean` | `false` | Enables the clear action |
| `onClear` | `() => void` | — | Callback triggered when the input is cleared |
| `prefix` | `ReactNode` | — | Content displayed before the input value |
| `suffix` | `ReactNode` | — | Content displayed after the input value |
| `withWrapper` | `boolean` | `true` | Enables or disables the FieldWrapper |

In addition to these properties, `Input` supports the standard native React `<input>` attributes.

## Native Input Attributes

Because `InputProps` extends the native React input attributes, standard HTML input properties can also be used.

For example:

```tsx
<Input
  type="email"
  name="email"
  autoComplete="email"
  maxLength={100}
  placeholder="Enter your email"
/>
```

Common native properties include:

- `name`
- `value`
- `defaultValue`
- `onChange`
- `required`
- `disabled`
- `readOnly`
- `type`
- `placeholder`
- `autoComplete`
- `maxLength`

This allows `Input` to preserve the familiar behavior of the native HTML input element.

## Accessibility

`Input` is designed around standard HTML input behavior and should be used with meaningful labels and accessible supporting content.

Recommended usage:

```tsx
<Input
  label="Email address"
  type="email"
  required
  helperText="We will never share your email."
/>
```

Labels should clearly describe the purpose of the field.

When using icons or custom adornments, ensure that purely decorative content is not exposed as meaningful information to assistive technologies.

Validation and required states should also be communicated consistently through the surrounding form semantics.

## Responsive Behavior

The `Input` component is designed to work within responsive form layouts.

When `fullWidth` is enabled:

```tsx
<Input
  label="Email"
  fullWidth
/>
```

the input uses the available width of its parent container.

Higher-level form layout systems are responsible for defining columns, spacing, and responsive field positioning.

## Form Engine Integration

`Input` is designed to be used as a building block for the FlowForge Form Engine.

A form definition can describe an input field using configuration similar to:

```ts
{
  type: "input",
  name: "firstName",
  label: "First name",
  required: true
}
```

The Form Builder can resolve the field definition to the corresponding FlowForge component.

```text
Form Definition
      ↓
Form Builder
      ↓
Field Registry
      ↓
Input
      ↓
Form Engine
      ↓
Validation / Dependencies / State
```

This keeps the Input component independent from business-specific form logic while allowing it to participate in dynamically generated forms.

---

## Validation

Validation is intentionally separated from the visual Input component.

The Input is responsible for displaying the validation state:

```tsx
<Input
  label="Email"
  error="Please enter a valid email address."
/>
```

The Form Engine can be responsible for defining and executing validation rules.

This separation allows the same Input component to work independently as well as inside dynamically generated forms.

## Design Considerations

`Input` is intentionally kept independent from business-specific validation and form logic.

Its primary responsibilities are:

1. Rendering the input control.
2. Managing visual and interaction states.
3. Providing a consistent API.
4. Supporting common input patterns.
5. Integrating with `FieldWrapper`.
6. Preserving standard native input behavior.
7. Supporting React ref access.

Higher-level concerns such as validation rules, dependencies, conditional rendering, persistence, and submission belong to the FlowForge Form Engine.

## Architecture Note

The `Input` component is part of the FlowForge UI layer.

It should remain independent from backend and database implementation details.

```text
┌──────────────────────────────┐
│          FlowForge UI        │
│                              │
│  Input / Select / Textarea   │
│             ↓                │
│        Form Builder          │
│             ↓                │
│         Form Engine          │
└──────────────┬───────────────┘
               │
               ↓
┌──────────────────────────────┐
│           Service            │
│                              │
│       API / Auth / ACL       │
│             ↓                │
│          Supabase            │
│             ↓                │
│         PostgreSQL           │
└──────────────────────────────┘
```

This separation allows the FlowForge UI layer and Service layer to evolve independently.
