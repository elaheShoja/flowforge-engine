# Textarea

The `Textarea` component is a flexible and reusable multi-line text input designed for FlowForge forms and applications.

It provides a consistent API for multi-line text input while supporting common form states, validation feedback, responsive layouts, manual resizing, automatic resizing, and configurable row limits.

---

## Overview

`Textarea` is one of the core form components of FlowForge.

It can be used independently or as part of a form generated by the FlowForge Form Builder.

### Key Features

- Labels
- Helper text
- Validation errors
- Required state
- Disabled state
- Configurable initial rows
- Automatic height adjustment
- Minimum row limit
- Maximum row limit
- Manual resizing
- Configurable resize direction
- Full-width layout
- Controlled and uncontrolled usage
- Native HTML textarea attributes
- Field wrapper integration

---

## Import

```tsx
import { Textarea } from "@/engine/components";
```

## Basic Usage

The simplest way to use `Textarea` is to provide a label and/or placeholder.

```tsx
<Textarea
  label="Description"
  placeholder="Enter your description..."
  rows={4}
/>
```

`Textarea` is intended for multi-line user input such as descriptions, comments, notes, messages, and other longer text content.

## Controlled Textarea

`Textarea` supports the standard React controlled component pattern.

```tsx
import { useState } from "react";
import { Textarea } from "@/engine/components";

export default function Example() {
  const [value, setValue] = useState("");

  return (
    <Textarea
      label="Description"
      value={value}
      onChange={(event) =>
        setValue(event.target.value)
      }
      placeholder="Enter a description..."
    />
  );
}
```

The value is controlled by React state and updated through the `onChange` callback.

## Rows

The `rows` property defines the initial or default number of visible rows.

```tsx
<Textarea
  label="Description"
  rows={5}
  placeholder="Enter a description..."
/>
```

For example:

```tsx
<Textarea
  label="Short Description"
  rows={3}
/>
```

creates a textarea with approximately three visible text rows.

```tsx
<Textarea
  label="Long Description"
  rows={6}
/>
```

creates a taller textarea with approximately six visible text rows.

When `autoResize` is disabled, `rows` determines the initial textarea height.

When `autoResize` is enabled, `rows` acts as the initial/default row count unless `minRows` is provided.

[Open Rows in Playground](/playground/textarea?focusId=textarea-rows)

## Full Width

`Textarea` uses a full-width layout by default.

```tsx
<Textarea
  label="Description"
  placeholder="Enter a description..."
/>
```

This is equivalent to:

```tsx
<Textarea
  label="Description"
  fullWidth
/>
```

When `fullWidth` is `true`, the textarea occupies the available width of its parent container.

```tsx
<Textarea
  label="Description"
  fullWidth
/>
```

When `fullWidth` is `false`, the textarea uses a content-based width while remaining constrained by the available space of its parent.

```tsx
<Textarea
  label="Description"
  fullWidth={false}
/>
```

[Open Full Width in Playground](/playground/textarea?focusId=textarea-full-width)

## Automatic Resize

`Textarea` supports automatic height adjustment through the `autoResize` property.

```tsx
<Textarea
  label="Description"
  autoResize
  placeholder="Start typing..."
/>
```

When `autoResize` is enabled, the textarea automatically adjusts its height according to its content.

As the user enters more text, the textarea grows.

When the content becomes shorter, the textarea can shrink accordingly.

[Open Auto Resize in Playground](/playground/textarea?focusId=textarea-auto-resize)

---

## Minimum Rows

`minRows` defines the minimum number of rows used by automatic resizing.

```tsx
<Textarea
  label="Description"
  autoResize
  minRows={3}
  placeholder="Start typing..."
/>
```

When `autoResize` is enabled, the textarea will not automatically shrink below the specified minimum.

`minRows` only affects automatic resizing.

[Open Minimum Rows in Playground](/playground/textarea?focusId=textarea-min-rows)

---

## Maximum Rows

`maxRows` defines the maximum number of rows used by automatic resizing.

```tsx
<Textarea
  label="Description"
  autoResize
  maxRows={8}
  placeholder="Start typing..."
/>
```

When the content exceeds the maximum height, the textarea stops growing and vertical scrolling becomes available.

`maxRows` only affects automatic resizing.

[Open Maximum Rows in Playground](/playground/textarea?focusId=textarea-max-rows)

---

## Minimum and Maximum Rows Together

`minRows` and `maxRows` can be used together with `autoResize` to define an automatic height range.

```tsx
<Textarea
  label="Description"
  rows={3}
  minRows={3}
  maxRows={8}
  autoResize
  placeholder="Start typing..."
/>
```

In this configuration:

- The textarea starts at approximately three rows.
- It can grow as content increases.
- It will not automatically shrink below three rows.
- It will grow up to eight rows.
- When the maximum height is reached, additional content can scroll vertically.

The general behavior is:

```text
Initial
  ↓
3 rows
  ↓
Content grows
  ↓
4 rows
  ↓
5 rows
  ↓
...
  ↓
8 rows
  ↓
Maximum reached
  ↓
Vertical scrolling
```

[Open Automatic Resize in Playground](/playground/textarea?focusId=textarea-auto-resize)

## Manual Resize

When `autoResize` is disabled, the textarea can be manually resized by the user according to the `resize` property.

```tsx
<Textarea
  label="Description"
  resize="vertical"
/>
```

The user can drag the resize handle to change the textarea size.

When manual resizing is enabled, `minRows` and `maxRows` do not restrict the user's manual resizing.

This keeps manual resizing independent from automatic content-based resizing.

[Open Resize in Playground](/playground/textarea?focusId=textarea-resize)

---

## Resize Direction

The `resize` property controls the direction in which the user can manually resize the textarea.

Supported values are:

| Value | Description |
| --- | --- |
| `none` | Manual resizing is disabled |
| `vertical` | Resize vertically |
| `horizontal` | Resize horizontally |
| `both` | Resize horizontally and vertically |

### No Resize

```tsx
<Textarea
  label="Description"
  resize="none"
/>
```

### Vertical Resize

```tsx
<Textarea
  label="Description"
  resize="vertical"
/>
```

### Horizontal Resize

```tsx
<Textarea
  label="Description"
  resize="horizontal"
/>
```

### Both Directions

```tsx
<Textarea
  label="Description"
  resize="both"
/>
```

[Open Resize Direction in Playground](/playground/textarea?focusId=textarea-resize)

## Auto Resize vs Manual Resize

`autoResize` and `resize` represent two different resizing behaviors.

### Automatic Resize

```tsx
<Textarea
  autoResize
  minRows={3}
  maxRows={8}
/>
```

The component controls its own height based on the content.

`minRows` and `maxRows` define the automatic height range.

### Manual Resize

```tsx
<Textarea
  autoResize={false}
  resize="vertical"
/>
```

The user controls the textarea size manually.

In this mode, `minRows` and `maxRows` do not restrict manual resizing.

This separation keeps automatic behavior predictable while allowing manual resizing when required.

[Open Auto Resize in Playground](/playground/textarea?focusId=textarea-auto-resize)

## Combining Rows and Auto Resize

`rows` can be used as the initial/default size while `autoResize` controls subsequent height changes.

```tsx
<Textarea
  label="Message"
  rows={3}
  autoResize
  minRows={3}
  maxRows={10}
/>
```

The textarea initially displays approximately three rows.

As the user enters more content, the component automatically grows up to ten rows.

## Without Field Wrapper

By default, `Textarea` can be used with the FlowForge field wrapper to provide field-level layout and supporting content.

When the surrounding UI already manages the field layout, the wrapper behavior can be disabled using `withWrapper`.

```tsx
<Textarea
  placeholder="Standalone textarea"
  withWrapper={false}
/>
```

This is useful when `Textarea` is placed inside a custom form layout or another component that already provides its own field structure.

## Native Textarea Attributes

`TextareaProps` extends the native React textarea attributes, so standard HTML `<textarea>` properties can also be used.

For example:

```tsx
<Textarea
  name="description"
  placeholder="Enter your description..."
  maxLength={500}
  autoComplete="off"
/>
```

Other native textarea properties such as `name`, `value`, `defaultValue`, `onChange`, `required`, `disabled`, `readOnly`, and `placeholder` are also supported.

---

## API

### TextareaProps

| Property | Type | Default | Description |
| --- | --- | --- | --- |
| `label` | `string` | — | Label displayed above the textarea |
| `helperText` | `string` | — | Supporting text displayed below the textarea |
| `error` | `string` | — | Validation error message |
| `fullWidth` | `boolean` | `true` | Makes the textarea occupy the available width |
| `rows` | `number` | `3` | Initial/default number of visible rows |
| `minRows` | `number` | — | Minimum rows used by automatic resizing |
| `maxRows` | `number` | — | Maximum rows used by automatic resizing |
| `autoResize` | `boolean` | `false` | Automatically adjusts height according to content |
| `resize` | `"none" \| "vertical" \| "horizontal" \| "both"` | `"vertical"` | Controls manual resize direction |
| `withWrapper` | `boolean` | `true` | Enables or disables the field wrapper |

In addition to these properties, `Textarea` supports the standard HTML `<textarea>` attributes.

---

## Resizing Behavior

The resizing behavior can be summarized as follows:

| Configuration | Behavior |
| --- | --- |
| `autoResize={false}` | User controls resizing through `resize` |
| `autoResize={true}` | Component controls height according to content |
| `autoResize={true} + minRows` | Automatic height cannot shrink below `minRows` |
| `autoResize={true} + maxRows` | Automatic height cannot grow beyond `maxRows` |
| `autoResize={true} + minRows + maxRows` | Automatic height stays within the defined range |
| `autoResize={false} + resize="none"` | User cannot resize |
| `autoResize={false} + resize="vertical"` | User can resize vertically |
| `autoResize={false} + resize="horizontal"` | User can resize horizontally |
| `autoResize={false} + resize="both"` | User can resize in both directions |

`minRows` and `maxRows` intentionally apply only to automatic resizing. Manual resizing remains independent from these limits.

## Validation

Validation is intentionally separated from the visual `Textarea` component.

The `Textarea` component is responsible for displaying the validation state:

```tsx
<Textarea
  label="Description"
  error="Description is required."
/>
```

The FlowForge Form Engine can be responsible for defining and executing validation rules.

This separation allows the same textarea component to work independently as well as inside dynamically generated forms.

## Accessibility

`Textarea` is designed to work with standard HTML textarea behavior and should be used with meaningful labels and accessible descriptions.

Recommended usage:

```tsx
<Textarea
  label="Description"
  required
  helperText="Enter a short description."
/>
```

When validation fails, the error message should provide a meaningful explanation of what needs to be corrected.

Native attributes such as `required`, `disabled`, `readOnly`, `name`, and `placeholder` should be used according to the semantic requirements of the form.

## Responsive Behavior

The component is designed to work within responsive form layouts.

When `fullWidth` is enabled:

```tsx
<Textarea
  label="Description"
  fullWidth
/>
```

the textarea uses the available width of its parent container.

When `fullWidth` is disabled:

```tsx
<Textarea
  label="Description"
  fullWidth={false}
/>
```

the textarea uses a content-based width while remaining constrained by its parent.

Responsive form layout and field positioning are handled by higher-level FlowForge form layout and Form Engine systems.

## Form Builder Integration

`Textarea` is intended to be used as a building block for the FlowForge Form Builder.

A future form definition may describe a field using configuration similar to:

```ts
{
  type: "textarea",
  name: "description",
  label: "Description",
  required: true,
  rows: 4
}
```

The Form Builder can then resolve the field definition to the corresponding FlowForge component.

```text
Form Definition
      ↓
Form Builder
      ↓
Field Registry
      ↓
Textarea
      ↓
Form Engine
      ↓
Validation / Dependencies / State
```

This keeps the `Textarea` component independent from business-specific form logic.

## Design Considerations

`Textarea` is intentionally kept independent from business-specific validation and form logic.

Its responsibilities are primarily:

1. Rendering the textarea.
2. Managing visual states.
3. Providing a consistent API.
4. Supporting multi-line text input.
5. Supporting automatic and manual resizing.
6. Integrating with `FieldWrapper`.
7. Exposing standard native textarea behavior.

Higher-level concerns such as validation rules, dependencies, conditional rendering, form state, persistence, and submission are handled by the FlowForge Form Engine.

## Architecture Note

The `Textarea` component is part of the FlowForge UI layer.

It should remain independent from the backend and database implementation.

```text
┌──────────────────────────────┐
│          FlowForge UI        │
│                              │
│  Input / Select / Textarea   │
│             ↓                │
│        Form Builder          │
│             ↓                │
│         Form Engine          │
└──────────────┬───────────────┘
               │
               ↓
┌──────────────────────────────┐
│           Service            │
│                              │
│       API / Auth / ACL       │
│             ↓                │
│          Supabase            │
│             ↓                │
│         PostgreSQL           │
└──────────────────────────────┘
```

This separation allows the FlowForge UI layer and Service layer to evolve independently.
