# Select

The `Select` component is a flexible and reusable selection field designed for FlowForge forms and applications.

It provides a consistent API for selecting one or multiple values while supporting searchable options, clearable selections, disabled options, option groups, Select All behavior, validation states, and controlled usage.

---

## Overview

`Select` is one of the core form components of FlowForge.

It can be used independently or as part of a form generated by the FlowForge Form Builder.

### Key Features

- Single-value selection
- Multi-value selection
- Searchable options
- Clearable selection
- Disabled Select state
- Disabled individual options
- Option groups
- Select All
- Filtered Select All
- Required state
- Validation errors
- Controlled usage
- Placeholder
- Selected value display
- Multi-select chips
- Keyboard-friendly option interaction
- Full-width field layout
- Field wrapper integration

## Basic Usage

The simplest way to use `Select` is to provide a list of options.

```tsx
const options = [
  {
    value: "react",
    label: "React",
  },
  {
    value: "typescript",
    label: "TypeScript",
  },
  {
    value: "javascript",
    label: "JavaScript",
  },
];

<Select
  label="Framework"
  options={options}
  placeholder="Select a framework..."
/>
```

## Select Options

Each Select option contains a `value` and a `label`.

```tsx
const options = [
  {
    value: "react",
    label: "React",
  },
  {
    value: "vue",
    label: "Vue",
  },
  {
    value: "angular",
    label: "Angular",
  },
];
```

The `value` is used as the selected value, while `label` is displayed to the user.

An option can also be disabled individually.

```tsx
const options = [
  {
    value: "available",
    label: "Available Option",
  },
  {
    value: "disabled",
    label: "Disabled Option",
    disabled: true,
  },
];
```

Disabled options remain visible but cannot be selected.

[Open Disabled Options in Playground](/playground/select?focusId=select-disabled-options)

## Searchable Select

The `searchable` property enables searching through the available options.

```tsx
<Select
  label="Search Framework"
  searchable
  options={options}
  placeholder="Search frameworks..."
/>
```

When enabled, the Select menu provides a search field that allows users to filter available options.

This is especially useful when the option list contains many items.

[Open Searchable Select in Playground](/playground/select?focusId=select-searchable)

---

## Clearable Select

The `clearable` property allows the current selection to be removed.

```tsx
<Select
  label="Framework"
  clearable
  options={options}
  placeholder="Select a framework..."
/>
```

For a single Select, clearing the value resets it to an empty string.

For a multi Select, clearing removes all selected values.

`clearable` can also be combined with `searchable`:

```tsx
<Select
  label="Framework"
  searchable
  clearable
  options={options}
  placeholder="Select a framework..."
/>
```

---

## Multi Select

The `multi` property enables multiple option selection.

```tsx
<Select
  label="Technologies"
  multi
  options={options}
  placeholder="Select technologies..."
/>
```

When multiple values are selected, they are displayed as chips inside the Select field.

The value of a multi Select is an array of strings.

```tsx
const [value, setValue] = useState<string[]>([]);

<Select
  label="Technologies"
  multi
  value={value}
  onChange={setValue}
  options={options}
/>
```

[Open Multi Select in Playground](/playground/select?focusId=select-multi)

---

## Multi Select with Search

`multi`, `searchable`, and `clearable` can be combined to provide a more powerful selection experience.

```tsx
<Select
  label="Technologies"
  multi
  searchable
  clearable
  options={options}
  placeholder="Select technologies..."
/>
```

This configuration allows users to:

1. Search for options.
2. Select multiple options.
3. Remove individual selections.
4. Clear all selected values.

```tsx
const groupedOptions = [
  {
    label: "Frontend",
    options: [
      {
        value: "react",

      },
      {
        value: "vue",
        label: "Vue",
      },
      {
        value: "angular",
        label: "Angular",
      },

  },
  {
    label: "Backend",
    options: [
      {
        value: "node",
        label: "Node.js",

      {
        value: "dotnet",
        label: ".NET",
      },
      {

        label: "Java",
      },
```

The grouped options can be passed directly to `Select`.


Groups can also be used with multi Select.

```tsx

  label="Technologies"
  multi
  searchable
  options={groupedOptions}
  placeholder="Select technologies..."
/>
```

## Select All

Multi Select supports Select All behavior through the `selectAll` property.

```tsx
<Select
  label="Select Technologies"
  multi
  searchable
  clearable
  selectAll={{
    enabled: true,
    scope: "filtered",
  }}
  options={options}
  placeholder="Select technologies..."
/>
```

When enabled, the Select menu provides an option for selecting or clearing all applicable options.

[Open Select All in Playground](/playground/select?focusId=select-select-all)

## Filtered Select All

The `scope` property controls which options are affected by Select All.

```tsx
selectAll={{
  enabled: true,
  scope: "filtered",
}}
```

With `scope: "filtered"`, Select All operates only on the options currently visible after filtering.

For example:

```text
All options
    ↓
User searches
    ↓
Filtered options
    ↓
Select All
    ↓
Only filtered options are selected
```

This behavior is useful when a Select contains a large number of options.

## Controlled Select

`Select` supports the standard React controlled component pattern.

```tsx
import { useState } from "react";
import { Select } from "@/engine/components";

const options = [
  {
    value: "react",
    label: "React",
  },
  {
    value: "typescript",
    label: "TypeScript",
  },
  {
    value: "javascript",
    label: "JavaScript",
  },
];

export default function Example() {
  const [value, setValue] = useState("");

  return (
    <Select
      label="Framework"
      value={value}
      onChange={setValue}
      options={options}
      clearable
      placeholder="Select a framework..."
    />
  );
}
```

The current value is stored in React state and passed back to the Select through the `value` property.

[Open Controlled Select in Playground](/playground/select?focusId=select-controlled)

## Controlled Multi Select

The same controlled pattern can be used with multi Select.

```tsx
import { useState } from "react";
import { Select } from "@/engine/components";

const options = [
  {
    value: "react",
    label: "React",
  },
  {
    value: "typescript",
    label: "TypeScript",
  },
  {
    value: "javascript",
    label: "JavaScript",
  },
];

export default function Example() {
  const [value, setValue] = useState<string[]>([]);

  return (
    <Select
      label="Technologies"
      multi
      value={value}
      onChange={setValue}
      options={options}
      placeholder="Select technologies..."
    />
  );
}
```

For multi Select, the controlled value is an array of selected option values.

## Single Select Value

A single Select uses a string value.

```tsx
const [value, setValue] = useState<string>("");

<Select
  value={value}
  onChange={setValue}
  options={options}
/>
```

An empty string represents no selected value.

---

## Multi Select Value

A multi Select uses an array of strings.

```tsx
const [value, setValue] = useState<string[]>([]);

<Select
  multi
  value={value}
  onChange={setValue}
  options={options}
/>
```

An empty array represents no selected values.

---

## Value Display

For a single Select, the selected option label is displayed inside the field.

```tsx
<Select
  value="react"
  options={options}
/>
```

The displayed value is:

```text
React
```

For a multi Select, selected values are displayed as chips.

```tsx
<Select
  multi
  value={["react", "typescript"]}
  options={options}
/>
```

The component manages the visual representation of selected values while the underlying value remains an array.

---

## Keyboard Interaction

The Select component is designed to support keyboard-friendly option interaction.

Users can interact with the option list using the keyboard according to the interaction behavior provided by the component.

Disabled options cannot be selected through normal option interaction.

The accessibility behavior may evolve as the FlowForge accessibility layer develops.

---

## Full Width

Select is designed to integrate with the available width of its parent form layout.

```tsx
<Select
  label="Framework"
  options={options}
  placeholder="Select a framework..."
/>
```

This allows Select to align consistently with other FlowForge field components such as `Input` and `Textarea`.

---

## Without Field Wrapper

By default, `Select` integrates with `FieldWrapper` for field-level layout and supporting content.

When the surrounding UI already manages the field layout, the wrapper can be disabled using `withWrapper`.

```tsx
<Select
  options={options}
  placeholder="Select an option..."
  withWrapper={false}
/>
```

This is useful when Select is embedded in a custom layout or another component already responsible for field presentation.

## API

### SelectProps

| Property | Type | Default | Description |
| --- | --- | --- | --- |
| `label` | `string` | — | Label displayed above the Select |
| `options` | `SelectOption[] \| SelectOptionGroup[]` | — | Available selection options |
| `value` | `string \| string[]` | — | Current selected value |
| `onChange` | `(value: string \| string[]) => void` | — | Callback triggered when the selection changes |
| `placeholder` | `string` | — | Text displayed when no value is selected |
| `multi` | `boolean` | `false` | Enables multiple selection |
| `searchable` | `boolean` | `false` | Enables option searching |
| `clearable` | `boolean` | `false` | Allows the current selection to be cleared |
| `disabled` | `boolean` | `false` | Disables the entire Select |
| `required` | `boolean` | `false` | Marks the field as required |
| `error` | `string` | — | Validation error message |
| `selectAll` | `SelectAllConfig` | — | Configures Select All behavior |
| `withWrapper` | `boolean` | `true` | Enables or disables the FieldWrapper |

### SelectOption

Individual options support:

| Property | Type | Default | Description |
| --- | --- | --- | --- |
| `value` | `string` | — | Internal value of the option |
| `label` | `string` | — | Text displayed to the user |
| `disabled` | `boolean` | `false` | Prevents the option from being selected |

### SelectOptionGroup

Option groups support:

| Property | Type | Description |
| --- | --- | --- |
| `label` | `string` | Label displayed for the group |
| `options` | `SelectOption[]` | Options contained in the group |

### SelectAllConfig

The `selectAll` configuration supports:

| Property | Type | Description |
| --- | --- | --- |
| `enabled` | `boolean` | Enables Select All behavior |
| `scope` | `"all" \| "filtered"` | Determines whether Select All applies to all options or only filtered options |

## Native and Standard Behavior

`Select` is a custom FlowForge selection component rather than a native HTML `<select>` element.

Its public API is designed around FlowForge form requirements while providing familiar selection behavior.

Application-specific data, validation rules, and form state remain outside the component.

---

## Validation

Validation is intentionally separated from the visual Select component.

The Select is responsible for displaying the validation state:

```tsx
<Select
  label="Framework"
  error="Please select a valid framework."
  options={options}
/>
```

The Form Engine is responsible for defining and executing validation rules.

This separation allows the same Select component to work independently as well as inside dynamically generated forms.

[Open Validation State in Playground](/playground/select?focusId=select-states&innerFocusId=select-states-error)

---

## Accessibility

`Select` is designed to provide keyboard-friendly selection behavior and meaningful field semantics.

Use a meaningful `label` so that the purpose of the field is clear to users and assistive technologies.

Recommended usage:

```tsx
<Select
  label="Preferred framework"
  required
  options={options}
  placeholder="Select a framework..."
/>
```

When options are disabled, they should remain visually distinguishable and unavailable for selection.

When using searchable Selects, the search interaction should remain understandable and accessible to keyboard users.

---

## Responsive Behavior

The component is designed to work within responsive form layouts.

Select uses the available space provided by its parent form layout.

For example:

```tsx
<div className="form-grid">

  <Select
    label="Framework"
    options={options}
    placeholder="Select a framework..."
  />

  <Select
    label="Language"
    options={options}
    placeholder="Select a language..."
  />

</div>
```

Responsive form layout and field positioning are handled by higher-level FlowForge form layout and Form Engine systems.

## Form Builder Integration

`Select` is intended to be used as a building block for the FlowForge Form Builder.

A future form definition may describe a selection field using configuration similar to:

```ts
{
  type: "select",
  name: "framework",
  label: "Framework",
  required: true,
  options: [
    {
      value: "react",
      label: "React",
    },
    {
      value: "vue",
      label: "Vue",
    },
  ],
}
```

The Form Builder can then resolve the field definition to the corresponding FlowForge component.

```text
Form Definition
      ↓
Form Builder
      ↓
Field Registry
      ↓
Select
      ↓
Form Engine
      ↓
Validation / Dependencies / State
```

This keeps the Select component independent from business-specific form logic.

## Design Considerations

`Select` is intentionally kept independent from business-specific validation and form logic.

Its responsibilities are primarily:

1. Rendering the selection field.
2. Managing selection interaction.
3. Supporting single and multi-value selection.
4. Supporting searching and clearing.
5. Supporting grouped and disabled options.
6. Providing Select All behavior.
7. Managing visual states.
8. Integrating with `FieldWrapper`.
9. Providing a consistent API for the FlowForge Form Engine.

Higher-level concerns such as validation rules, dependencies, conditional rendering, form state, persistence, and submission are handled by the FlowForge Form Engine.

## Architecture Note

The `Select` component is part of the FlowForge UI layer.

It should remain independent from the backend and database implementation.

```text
┌──────────────────────────────┐
│          FlowForge UI        │
│                              │
│  Input / Select / Textarea   │
│             ↓                │
│        Form Builder          │
│             ↓                │
│         Form Engine          │
└──────────────┬───────────────┘
               │
               ↓
┌──────────────────────────────┐
│           Service            │
│                              │
│       API / Auth / ACL       │
│             ↓                │
│          Supabase            │
│             ↓                │
│         PostgreSQL           │
└──────────────────────────────┘
```

This separation allows the FlowForge UI layer and Service layer to evolve independently.
